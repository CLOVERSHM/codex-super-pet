# 管理面板

左侧管理面板提供历史采集、采集加白、进度报告三个页签。

## 历史采集

选择 Codex 项目与日期（Asia/Shanghai，自起始日零点至结束日次日零点）。
`POST /api/management/history` 由人发起，后台任务最多读取所选范围的
5000 条用户输入；超过限制需缩小范围。元数据先筛选，正文按准确会话和消息 ID
只读查询，不读工具、推理、附件或运行上下文。摘要最多240字，基础敏感字段脱敏，
不是完备DLP。来源是本机内部投影数据库，远程/云端/未投影内容不保证覆盖。

当前没有模型分析后端：只运行透明的本地规则初筛，标识需求线索、闲聊线索、
待人工分析，不能称为AI语义判断。用户查看原会话、填写短标题和描述，
确认新增/修改/归档或忽略；确认录入复用intake版本和准确关联会话门禁。
修改/归档仅允许本地需求且已人工确认关联原会话；不会从标题猜测需求。
不会自动批准、改进度或发送消息。重复消息内容去重，编辑后的消息重新待审阅。
重复候选录入幂等；崩溃恢复不自动重新读取历史。

`GET /api/management` 查询任务、候选、报告；
`POST /api/management/jobs/<id>/cancel` 取消后保留已生成候选；
`POST /api/management/candidates/<id>` 人工确认处理。

## 项目加白

`POST /api/catalog` 的布尔字段 `capture_excluded`，沿用项目 revision 并发校验。
加白含义是排除采集，不是放行。增量采集在读正文前检查；加白期间输入只标记已见，
取消加白不自动回填期间内容。历史任务逐条检查当前项目设置和准确归属，
录入前再次检查。已保存摘要不物理清除，但加白后候选/采集接口不展示摘要，
新报告也不引用这些聊天；已有需求保留。既有报告是生成时快照，未自动改写。
主动在控制台手动新建需求不属于采集，仍可使用。

## 报告

`GET /api/management/chats` 只读会话目录；
`POST /api/management/report` 选择 projects/chats/requirements 范围、
日报/周报/自定义类型及日期，生成本地Markdown，可预览与下载。
日期独立于报告类型：选择“周报”不会偷偷改写用户日期。

报告不回读原始历史正文、不调用模型：期间账本事件和测试声明单独列出，
生成时当前节点、阻塞、待审批单独列出，不冒充历史期末快照或生产已发布；
输入摘要只属于输入线索。不存在记录/会话来源不可用时明确标记覆盖缺口。
最多展开200条期间输入，其余提示缩小范围。报告保存在私有SQLite，
不提交Git或打包；原始账本与审批不变。

## 验证

使用临时合成项目/会话，测试范围边界、排除/取消/重启、去重、人工角色、
消息归属变化、版本与关联校验、日报周报覆盖缺口和浏览器操作。
不扫描真实历史、审批真实需求、发送消息或修改业务记录。
