# 会话工作台与状态回报

## 边界

首页按 Codex 本机项目元数据展示项目、会话、当前任务。右侧工作区提供
状态分类、关键词/项目筛选、标题/状态/项目/最近活动排序的会话表格，
点击行在抽屉查看状态原因与下一步，行末使用经 UUID 校验的
`codex://threads/` 链接打开原会话。管理面板与需求账本在同页右侧
按需载入同源 `/legacy`，切换不清空原有表单状态；`/legacy` 也可独立访问。
仅旧页面允许同源嵌入，其余页面及 API 仍禁止嵌入。旧账本与协调记录不迁移、不删除。
首次打开当前浏览器时，欢迎向导默认预选上海时区近七个自然日（含当天）
及未加白项目，用户可以调整日期/项目或跳过；明确点击“开始采集”后调用
既有 human `POST /api/management/history`。初始化标记仅存浏览器
`localStorage`，右上角帮助图标可重新打开。扫描使用本地规则初筛并生成
待审阅候选，不是跨会话自动调用大模型判断进度、完成状态或自动录入需求。
不会在服务启动、打开页面或浏览引导时擅自回读历史正文。
对账只读取 `state_5.sqlite` 的会话元数据和 `thread_history_1.sqlite` 中
`userMessage` 行的 ID、时间、更新序号与长度，不读取该行正文或工具/推理正文。
当前桌面索引是内部适配器，格式变化时停止回报并显示异常，不猜测会话归属。

## 对账与回报

启动、每 600 秒和已启用增量采集的轮询后，对每个未加白项目的会话输入元数据
计算 SHA-256，结合本地单调观察版本。手动“立即对账”也是只读索引刷新。新输入或编辑令已有回报
过期，页面显示“待回报”；历史上从未回报显示“待核实”。
项目归属变化也令旧回报过期；变化后恢复原值不会让旧回报复活。
加白删除面板索引及旧回报，取消加白不恢复旧状态。
哈希不能证明轮次结束、任务完成，也不能覆盖未投影到本机索引的远程聊天。
长度与更新序号只是变化标记，不是消息内容加密校验；碰撞或同长无序号变更会漏报。

通用 `session-status` 在准确会话身份可用时读取
`GET /api/board/context?thread_id=<UUID>`，取得项目、最新轮次与观察哈希，
通过 agent bridge 向 `POST /api/board/report` 显式提交
`thread_id, project_id, turn_id, observation_hash, task_key, workflow, stage, state,
summary, reason, next_action, evidence, skill_id`。统一状态为 `in_progress`,
`completed`, `blocked`, `waiting_approval`, `waiting_user`, `unverified`；
原因在阻塞、审批、待补充时必填。状态是技能声明，不能自动执行审批或生产动作。
同一输入的不同内容回报被拒绝，重试相同内容幂等；新任务等待新输入版本。
若宿主不能给出准确当前会话 ID，技能不回报，面板保持“待核实”。
目前**没有**已验证的跨所有聊天可靠轮次结束触发，也未保证技能每轮自动调用。

## 项目专属工作流

`tools/create_project_skill.py` 生成便携专属 skill 与 `contract.json`，
`tools/validate_project_skill.py` 校验契约。专属流程自己决定工作细节；
平台只校验该 skill 属于项目、人工显式启用、统一状态字段及版本。
平台不代替业务流程判断、不安装生成的技能；需将技能提供给对应会话并
确保实际调用，才能出现回报。客户端项目配置使用 `/api/session-skills` 目录。
历史采集仍是旧管理面板的人工审阅路径，不能视为自动状态分析。

## 历史复核

`POST /api/board/historical-review` 仅接受 human token，且必须带当前
`thread_id, project_id, observation_hash`；短结论、具体原因/下一步和
脱敏证据引用由人工逐条审阅历史用户输入及答复后提交。它保存在独立
`board_history_reviews` 表，`source` 明示“历史复核”，不是通用 skill 的
跨会话调用。实时 skill 的当前回报优先；输入或项目归属变化使历史复核
立即过期，加白删除复核记录。没有充分证据时保持待核实，不能把
`final_answer` 或答复末尾的“已”直接当成完成证明。

## 验收范围

合成 SQLite 测试覆盖索引变化、回报幂等、归属变化、加白、来源故障、
角色限制与专属 skill 项目门禁。打包先于全量 unittest；不使用真实聊天
内容、项目专属记录或生产操作。宿主事件接入和准确桌面跳转仍需真实环境
分别验收；定时对账不能替代它们。
