# 本机全局聊天采集（2026-10-17）

启动参数 `--capture-chats`，或数据目录的 `capture-enabled` 标记，启用只读采集。
删除标记并重启即关闭；不修改 Codex 配置或数据库，不接管线程，不安装插件。

当前版本以 state_5.sqlite 会话元数据和 thread_history_1.sqlite 用户输入投影为来源。
每 3 秒检查本机所有会话；Web 每 15 秒刷新，故正常可见延迟约 3–18 秒。
这是实验本机索引适配，不是稳定官方全局事件订阅；云端、远程、尚未投影到该索引的
会话和临时消息不保证覆盖。格式异常明确报错，不扫描 rollout 或降级读取全历史。

首次启动记录已有输入的稳定 ID/变更标记，不读取旧正文；只采集之后新增或修改的
用户文本。过滤工具、推理、附件及环境上下文，最多保留 240 字经基础隐藏处理的摘要；
该处理不是完备 DLP，摘要仍可能含业务信息，仅存本机私有目录，不导出到 Git/ZIP。
不会调用外部模型服务，不自动分类天气闲聊为需求。新输入进入“待分析”队列；
现有语义技能仍须模型执行并提交独立的需求变更建议，人工采纳后才产生需求。

新输入展示和正式需求变更是两个阶段；本轮接通前者，不声称自动语义分析已接通。
首次已有会话目录只是元数据，不把历史标题当成需求。未明确项目归属不按 cwd 猜。
Web 只显示最近 200 条输入，本地去重和队列保留。关闭采集不自动删除已有摘要。
目标变化、Web→Codex 发送、可信执行审批门禁不属于该只读采集器。

GET `/api/capture` 受现有 bearer 授权，返回健康、会话目录和待分析输入。
测试使用临时合成索引，不向真实聊天发送测试任务。
